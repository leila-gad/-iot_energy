# INPT Campus Energy Monitoring — Virtual IoT Lab


## What it simulates

- Four campus usage profiles: classrooms, laboratory, library, and residence.
- Three-phase meter readings for L1/L2/L3: voltage (V), current (A), active power (kW), and power factor.
- Meter-level frequency (Hz), total active power (kW), and cumulative energy (kWh).
- MQTT transport topics labelled `wifi` or `lora`.
- MQTT broker (Mosquitto) → Python collector → InfluxDB time-series database → Grafana dashboards.

**Important:** all readings are synthetic. `TRANSPORT=lora` simulates a LoRa-labelled data path in software; it does not emulate LoRa radio propagation or use physical LoRa hardware. This is not a replacement for calibrated real electrical measurements and must never be connected to electrical equipment.

## Requirements

- Windows 10/11 with Docker Desktop installed and running, or Linux with Docker Engine and the Compose plugin.
- Internet access on first run so Docker can pull images.

## Run on Windows

### Prerequisites

- Windows 10 or Windows 11
- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- Docker Compose (included with Docker Desktop)

### 1. Install and start Docker Desktop

Install Docker Desktop and launch it. Wait until the Docker engine is running before continuing.

Verify that Docker is available by opening PowerShell and running:

```powershell
docker --version
docker compose version
```

### 2. Open the project folder

Extract the project to a simple path, for example:

```text
C:\iot_energy_virtual_lab
```

Open PowerShell in the folder containing `docker-compose.yml`.

**Important:** If the project contains two nested folders named `iot_energy_virtual_lab`, enter the inner folder before running Docker Compose.

For example:

```powershell
cd "$HOME\Downloads\iot_energy_virtual_lab\iot_energy_virtual_lab"
```

Verify that you are in the correct directory:

```powershell
Get-ChildItem
```

You should see `docker-compose.yml`, `.env.example`, and the project folders, including `simulator`, `collector`, and `grafana`.

Docker Compose must be run from the directory containing `docker-compose.yml`, unless you explicitly specify the file path.

### 3. Configure the environment

Create the local environment file from the example:

```powershell
Copy-Item .env.example .env
```

This command is required only the first time, or whenever you need to recreate the local environment file. Do not overwrite an existing `.env` file containing your own configuration.

### 4. Start the platform

From the directory containing `docker-compose.yml`, run:

```powershell
docker compose up --build -d
```

Docker Compose builds the required images and starts the services in the background.

For subsequent launches, if the images are already built and no rebuild is needed, you can use:

```powershell
docker compose up -d
```

### 5. Check the containers

Check the status of the services:

```powershell
docker compose ps
```

To follow the simulator and collector logs, run:

```powershell
docker compose logs -f simulator collector
```

Press `Ctrl+C` to stop following the logs. This does not stop the containers.

### 6. Open Grafana

Open the following address in your browser:

**http://localhost:3000**

Default login:

- **Username:** `admin`
- **Password:** `admin123`

Change the default password if you keep the platform running beyond a local demonstration.

### 7. Open the dashboard

Open the dashboard named:

**INPT Campus Energy Monitoring - Virtual Lab**

Allow approximately 10–30 seconds for the first measurements to appear.

The dashboard displays simulated campus energy measurements, including:

- Active power by building (kW)
- Cumulative energy by building (kWh)
- Three-phase voltage (V)
- Three-phase current (A)

The measurements are generated by the Python simulator and are not collected from physical sensors.

### 8. Stop the platform

To stop and remove the running containers, execute:

```powershell
docker compose down
```

Your project files remain on disk. Persistent database data is retained if the Compose configuration uses a persistent volume.

### Troubleshooting

**Error: `no configuration file provided: not found`**

This means Docker Compose cannot find `docker-compose.yml` in the current directory.

Check your location:

```powershell
Get-Location
```

List the files:

```powershell
Get-ChildItem
```

If you are in the outer project folder, enter the inner folder:

```powershell
cd .\iot_energy_virtual_lab
```

Then retry:

```powershell
docker compose up --build -d
```

## Run on Linux

```bash
cp .env.example .env
docker compose up --build -d
docker compose ps
docker compose logs -f simulator collector
```

Then open `http://localhost:3000` and log in with `admin` / `admin123`.

## Switch the transport label

Edit `.env`:

```dotenv
TRANSPORT=lora
PUBLISH_INTERVAL_SECONDS=5
```

Then recreate the simulator:

```bash
docker compose up -d --build simulator
```

Set `TRANSPORT=wifi` to switch back. Both modes use MQTT in this virtual demo; the label lets you demonstrate how the topic structure could distinguish meter transport technologies.

## Useful checks

- Simulator output: `docker compose logs -f simulator`
- Collector output: `docker compose logs -f collector`
- InfluxDB health: open `http://localhost:8086/ping` (a successful response is normally HTTP 204).
- MQTT topics: `campus/energy/<wifi-or-lora>/<building>`
- InfluxDB database: `energy`; measurement: `energy_readings`.

To stop the platform:

```bash
docker compose down
```

To remove the containers **and erase stored InfluxDB/Grafana data**:

```bash
docker compose down -v
```

## Architecture

```text
Virtual 3-phase meters (Python)
   └── MQTT topic per building / transport label
         └── Mosquitto broker
               └── Python collector
                     └── InfluxDB (energy_readings)
                           └── Grafana dashboards
```

## Project limitations and next steps

- The article describes real meter hardware, campus installation, Wi-Fi/LoRa communication, data storage, Grafana visualization, and a data downloader. This starter reproduces the **software pipeline** and dashboards, not the physical electrical measurement hardware.
- The current version does not implement LoRaWAN, RS-485/Modbus, a PLC/SCADA connection, authentication for MQTT, or the article's separate downloader desktop application.
- Add a data export/downloader or anomaly-detection module as a next project step. For real measurements, use qualified supervision and properly rated isolated metering equipment; do not experiment directly on mains electricity.
